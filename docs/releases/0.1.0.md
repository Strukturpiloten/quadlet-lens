# QuadletLens 0.1.0

This is the first public QuadletLens library release. It establishes the supported 0.1.x API line
for BoxFerry and other Rust tools that need native Quadlet processing without invoking Podman or
systemd during normal library use.

## Included capabilities

- ordered, source-aware systemd-style syntax with comments, repeated keys, continuations, source
  spans, exact preservation, and deterministic conservative rendering;
- native typed `.container`, `.pod`, `.network`, and `.volume` documents that retain generic
  systemd sections and unknown entries;
- conservative systemd-specifier, path, and native unit-reference classifications;
- exact-name document sets with resolved, missing, and ambiguous relationship states;
- a strict capability catalogue with `podmanMinimumVersion` and optional
  `podmanMaximumVersion` evaluation, fallbacks, known-bug precedence, and explicit evidence gaps;
  and
- a reproducible generator harness covering the first-conversion subset on all 20 Podman patch
  releases from 5.4.0 through 6.0.2.

## Compatibility evidence

Podman 5.4.0 is the fixed minimum. The built-in catalogue has finite reviewed coverage through
Podman 6.0.2. Fourteen exact official Podman images cover 5.4.0 through 5.8.2; six exact release
source commits cover 5.8.3 through 6.0.2 using a digest-pinned Go builder. The generator matrix
verifies only the documented first-conversion forms, not every Quadlet capability.

## Known limits

- Native typed models do not yet cover `.image`, `.build`, `.kube`, or `.artifact` units.
- Health-command values and generic systemd readiness/ordering semantics remain opaque and
  separate.
- Typed target-aware rendering is not implemented; the current canonical renderer normalizes
  valid syntax structure without rewriting values.
- Generator success is not runtime proof. Rootless/rootful, SELinux, networking, cgroup, and
  systemd activation behavior remain later test tiers.
- No API beyond the documented 0.1.x contract carries a 1.x stability promise.
