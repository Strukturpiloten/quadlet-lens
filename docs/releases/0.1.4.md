# QuadletLens 0.1.4

QuadletLens 0.1.4 adds the native readiness and ordering primitives needed for source service
dependencies without pretending that Podman, systemd, and Compose share one lifecycle model.

## Added

- `ContainerKey::Notify` for native container startup notification behavior.
- Capability `quadlet.container.notify-healthy` for `Notify=healthy` from Podman 5.4.0 through the
  finite current catalogue ceiling, Podman 6.0.2.
- `SystemdUnitKey::{Requires, Wants, After}` and
  `QuadletDocumentBuilder::push_systemd_unit` for typed dependency and ordering construction.
- Separate `systemd.unit.requires`, `systemd.unit.wants`, and `systemd.unit.after` capability
  records.
- Parser, builder, renderer, catalogue, and public-consumer tests for the additive surface.
- Real-generator fixtures accepted by all 20 recorded Podman patch releases from 5.4.0 through
  6.0.2.

## Compatibility

The public changes are additive within the documented QuadletLens 0.1.x API. Existing callers do
not need to change. Rust 1.85.0 and Podman 5.4.0 remain the minimum supported versions; Podman 5.4
is not a maximum.

## Semantic boundary

`Notify=healthy` delays the generated service's readiness notification until Podman reports a
healthy container. `Requires` and `Wants` select strong and weak activation relationships, while
`After` expresses ordering independently. The release proves generator pass-through and generated
readiness arguments; it does not claim runtime validation of every systemd failure, cycle, stop,
or restart-propagation behavior.

Compose-managed `restart: true` and `service_completed_successfully` therefore remain conversion
policy decisions rather than implicit QuadletLens mappings.
