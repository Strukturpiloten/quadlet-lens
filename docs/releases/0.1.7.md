# QuadletLens 0.1.7

QuadletLens 0.1.7 adds the native container-label boundary needed to preserve Compose service
labels during BoxFerry conversion.

## Added

- `ContainerKey::Label` for source-aware parsing and typed programmatic construction.
- Ordered repeatable `Label=` entries without duplicate-name merging.
- Capability ID `quadlet.container.label`, with native evidence from Podman 5.4.0 through the
  finite current catalogue ceiling, Podman 6.0.2.
- Parser, builder, catalogue, and public-consumer tests.
- Native label fixtures for separate entries, an empty value, and JSON-like quote/whitespace
  content across every recorded Podman patch release in the supported range.
- An explicit generator-presentation boundary: 5.4.x emits the tested label's whitespace literally,
  while 5.5.0 and later use the equivalent systemd `\x20` escape.

## Compatibility

The public change is additive within the documented QuadletLens 0.1.x API. `ContainerKey::Label`
is appended after all published variants, preserving their numeric discriminants. Existing callers
do not need to change. Rust 1.85.0 and Podman 5.4.0 remain the minimum supported versions; Podman
5.4 is not a maximum.

## Semantic boundary

Each label remains exact caller-supplied native text. QuadletLens does not validate reverse-DNS
naming recommendations, merge duplicate names, or infer whether a label belongs on a container,
network, or volume. Generator evidence proves the corresponding Podman command arguments, not
runtime inspection behavior.
