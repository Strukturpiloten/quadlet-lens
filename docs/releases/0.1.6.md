# QuadletLens 0.1.6

QuadletLens 0.1.6 closes the pod-level user-namespace gap exposed by BoxFerry's explicit pod
grouping and adds the native secret boundary needed for Compose secret migration. Podman uses the
pod's user namespace for joined containers, so container-level `UserNS=` alone cannot preserve
grouped namespace intent.

## Added

- `PodKey::UserNS` for source-aware parsing and typed programmatic construction.
- Singleton validation and deterministic `UserNS=` rendering in `[Pod]`.
- Capability ID `quadlet.pod.userns`, with native evidence from Podman 5.4.0 through the finite
  current catalogue ceiling, Podman 6.0.2.
- Parser, builder, duplicate-singleton, catalogue, and public-consumer tests.
- A pod-specific `UserNS=auto:size=8192` fixture that must generate the distinct
  `--userns auto:size=8192` command fragment across the recorded Podman matrix.
- Repeatable `ContainerKey::Secret` parsing, construction, and deterministic rendering.
- Capability ID `quadlet.container.secret` for mounted-file and environment-variable exposure,
  including target, UID, GID, and mode option spellings.
- Two secret fixtures that must generate distinct `--secret` arguments across the complete
  recorded Podman matrix.

## Compatibility

The public change is additive within the documented QuadletLens 0.1.x API. Existing callers do not
need to change. Rust 1.85.0 and Podman 5.4.0 remain the minimum supported versions; Podman 5.4 is
not a maximum.

## Semantic boundary

The value remains exact caller-supplied native text. QuadletLens does not determine whether a
namespace mode is usable for a particular rootless/rootful host or subordinate-ID configuration.
Secret values likewise remain caller-supplied native text; QuadletLens does not create, read,
rotate, or check the existence of Podman secrets. Generator evidence proves the corresponding
Podman command arguments, not runtime activation or secret availability.
