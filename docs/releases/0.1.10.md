# QuadletLens 0.1.10

QuadletLens 0.1.10 expands the source-aware native container model, validated generation API,
capability catalogue, and exact real-generator evidence for lifecycle, execution, resource, and
device settings. All new values remain native Quadlet values; this release does not add
cross-format conversion policy or runtime inspection.

## Added

- Singleton `Entrypoint` and `RunInit` keys. Entrypoint stays distinct from `Exec`; `RunInit`
  preserves omission, literal values, and raw noncanonical one-line text without interpreting
  runtime init behavior.
- Singleton `StopSignal` and `StopTimeout` keys, retaining exact signal spelling and authored zero
  timeouts without claiming runtime timing, zero/default equivalence, or Compose lifecycle
  equivalence.
- Singleton `Pull`, `PidsLimit`, and `HostName` keys. Pull policy text and hostnames remain opaque;
  the focused PID-limit helper safely constructs only `-1` or a nonzero arbitrary-precision
  ASCII-decimal spelling.
- Separate singleton container and pod `ShmSize` keys plus a focused non-negative decimal-size
  helper with optional lowercase `b`, `k`, `m`, or `g`. Explicit zero remains distinguishable as
  Podman's documented unlimited shared-memory value.
- Repeatable container `DropCapability`, `AddCapability`, `Tmpfs`, `Sysctl`, `Ulimit`, and
  `AddDevice` keys. Repetition, insertion order, duplicates, exact one-line text, and applicable
  empty reset assignments are preserved without splitting, normalization, semantic validation,
  or runtime interpretation.
- Singleton container `Memory` plus a focused positive arbitrary-precision decimal-size helper
  with optional lowercase `b`, `k`, `m`, or `g`. Parsed and raw values remain opaque.

## Evidence boundary

The digest-pinned/exact-source generator matrix covers every recorded Podman patch from 5.4.0
through 6.0.2. Across that complete 20-patch range it protects the supported `Entrypoint`,
`RunInit`, stop signal/timeout, pull policy, PID limit, hostname, shared-memory, capability,
tmpfs, sysctl, ulimit, and device forms. The assertions cover exact logical Podman arguments,
ordering, duplicate counts, empty-reset effects, and rejected alternate forms where applicable.

- The entrypoint fixture emits exactly one of the two observed equivalent JSON-array encodings;
  `RunInit=true` emits one `--init`, and `RunInit=false` emits one `--init=false`.
- `SIGUSR1` and numeric signal `9`, timeout `37` and zero, all four pull policies, PID limits `127`
  and `-1`, hostname `app.example`, positive and zero container shared-memory sizes, and a
  pod-owned shared-memory size each emit exactly their isolated expected argument.
- Capability fixtures emit four ordered lowercase drops, four ordered lowercase additions, or one
  `--cap-drop all` before one `--cap-add cap_net_bind_service`, with no opposite or extra forms.
- Reset fixtures leave only the final tmpfs and sysctl arguments, the two ordered final ulimits,
  and the two ordered final device mappings; no pre-reset, empty, duplicate, or alternate form is
  emitted.

`Memory` has a narrower native boundary matching its upstream introduction: Podman 5.4.x rejects
or excludes the key and emits no memory argument, while every recorded patch from 5.5.0 through
6.0.2 emits exactly one final `--memory 16777216b` argument from the isolated fixture.

These are parser, catalogue, tagged-source, and dry-run generator claims. They do not establish
container runtime behavior, resource enforcement, rootless/rootful equivalence, cgroup or kernel
effects, SELinux behavior, device availability, CDI behavior, registry behavior, or cross-format
mapping fidelity.

## Compatibility

The public changes are additive within the documented QuadletLens 0.1.x API. New
`ContainerKey`/`PodKey` variants were appended after published discriminants, preserving the
numeric values of earlier variants. Raw `EntryValue` construction remains available alongside the
new focused safe helpers.

Rust 1.85.0 remains the minimum supported Rust version. Podman 5.4.0 remains the product support
floor, while the reviewed finite capability ceiling remains Podman 6.0.2; the `Memory` capability
is reported only from Podman 5.5.0.
