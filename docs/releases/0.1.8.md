# QuadletLens 0.1.8

QuadletLens 0.1.8 adds a pinned real-world Quadlet corpus and corrects the workload-source model
for containers backed by a host root filesystem instead of an image.

## Added

- A license-reviewed catalogue of 35 immutable `.container`, `.pod`, `.network`, and `.volume`
  files from ten upstream, vendor, distribution, platform, organization-example, and community
  projects.
- An opt-in `cargo ci-real-world-quadlet` test that verifies every Git blob, required feature
  marker, syntax parse, byte-preserving render, canonical reparse, typed model, and native
  document-set relationship without starting workloads.
- `ContainerKey::Rootfs` for source-aware parsing and typed programmatic construction.
- Capability ID `quadlet.container.rootfs`, with documentation and complete real-generator
  evidence for Podman 5.4.0 through 6.0.2.
- Structured `QLM0006` and `QLM0007` diagnostics for conflicting `Image`/`Rootfs` entries and an
  empty `Rootfs` value.

## Fixed

- A valid rootfs-backed container no longer receives `QLM0002`. A `.container` unit now requires
  exactly one workload source: `Image=` or `Rootfs=`.

## Compatibility

The public change is additive within the documented QuadletLens 0.1.x API.
`ContainerKey::Rootfs` is appended after all published variants, preserving their numeric
discriminants. The `QLM0002` correction intentionally changes invalid output for a document that
the Podman 5.4 and current manuals accept. Existing image-backed callers do not need to change.
Rust 1.85.0 and Podman 5.4.0 remain the minimum supported versions; Podman 5.4 is not a maximum.

## Semantic boundary

`Rootfs` remains exact caller-supplied Podman text. QuadletLens classifies its broad path form but
does not inspect the host filesystem, parse overlay-rootfs options, verify SELinux labeling, or
claim runtime success. The real-world corpus proves ingestion, not that third-party units are
correct or portable across hosts.
